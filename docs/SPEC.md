# さわかみ投信・月次課題チェッカー 仕様書

更新日: 2026-09-05  
状態: ドラフト

## 1. 対象メール

- 件名: `長期投資家デビュープロジェクト｜課題アンケート提出完了`
- 送信元: `noreply@sawakami.co.jp`
- 件名中の区切り文字は全角の `｜` とする。

## 2. 対象期間

確認処理を実行した日時が属する月を対象月とする。

対象期間は、日本時間における次の半開区間とする。

```text
対象月1日 00:00:00 以上、翌月1日 00:00:00 未満
```

例として2026年9月の確認では、2026年9月1日 00:00:00以上、2026年10月1日 00:00:00未満に受信したメールだけを対象とする。8月以前のメールは判定に使用しない。

## 3. 判定結果

判定結果は以下の3種類とする。

### 完了

対象期間内に、件名と送信元が一致するメールが1件以上存在する。

表示例:

```text
9月分の課題アンケートは提出済みです。
完了メールは9月12日 10:41に届いています。
```

完了メールは対象月に1件届く前提とし、一致したメールの受信日時を表示する。複数の完了メールに対する特別な処理は行わない。

### 未確認

Gmailの確認処理には成功したが、対象期間内に一致するメールが存在しない。

表示例:

```text
9月分の課題アンケート提出完了メールを確認できませんでした。
```

### 確認エラー

認証、API、通信などの問題により、Gmailの検索結果を取得できなかった。

表示例:

```text
Gmailの確認に失敗しました。手動で確認してください。
```

## 4. 自動確認と通知

### 毎月15日

- 当月分を確認する。
- 完了、未確認、確認エラーのいずれかを通知する。
- GmailとSlackは別々に送信を試みる。
- 判定結果を対象年月とともにデータベースへ保存する。

### 毎月25日

- データベースに保存された当月15日の判定結果を確認する。
- 15日の判定結果が完了で、SlackまたはGmailの少なくとも一方への通知が成功している場合は、Gmail検索と通知を行わない。
- 15日の判定結果が完了でも、SlackとGmailの通知が両方失敗している場合は、当月分を改めて確認する。
- 15日の判定結果が未確認または確認エラーの場合は、当月分を改めて確認する。
- 15日の記録が存在しない場合も、当月分を確認する。
- 確認を行った場合は、25日時点の完了、未確認、確認エラーのいずれかを通知し、結果を保存する。
- 25日のSlack通知とGmail通知が両方失敗しても、26日以降の追加の定期確認・通知は行わない。利用者がGmailを手動で確認する。

### 通知時刻

- 希望時刻は19:00とする。
- タイムゾーンは `Asia/Tokyo` を使用する。
- Vercel Hobbyを利用するため、実際の実行が19:00から19:59までの範囲になることを許容する。

## 5. 手動確認

- 本人用画面に「今すぐ確認」ボタンを表示する。
- 押下すると当月分のGmail検索を実行し、画面に結果を表示する。
- 押下時にSlackとGmailへ確認結果を即時通知する。
- 手動確認は補助機能と位置づけ、自動通知を主要な利用方法とする。
- 手動確認結果は15日・25日の定期確認記録を変更せず、25日の実行要否にも影響させない。

## 6. Slack通知

- 投稿先は利用者本人だけが閲覧できる場所とする。
- 推奨は、個人用Slackワークスペース内の専用チャンネルとする。
- Slack連携が設定されていない場合は通知をスキップし、処理を失敗させない。
- Slack連携が設定されているのに投稿できなかった場合は、Slack通知失敗として扱う。
- Slack通知失敗によって、Gmail検索結果やGmail通知の結果を変更しない。

## 7. Gmail通知

- 当月の判定結果を、本人が指定するメールアドレスへ送信する。
- Gmail通知失敗によって、Gmail検索結果やSlack通知の結果を変更しない。
- 宛先メールアドレスは未決定。

## 8. 検索対象外

- Gmailの迷惑メールに分類されているメールは検索対象外とする。
- Gmailのゴミ箱に入っているメールは検索対象外とする。
- 件名または送信元が指定値から変更された場合の自動追従は行わない。

## 9. 定期確認結果の保存

- データベースには定期確認の結果だけを保存する。
- 1件の記録は、対象年月、確認日種別、判定結果、確認実行日時、完了メール受信日時、各通知先の成否を持つ。
- 対象年月と確認日種別の組み合わせは重複させない。
- 確認日種別は15日または25日とする。
- 判定結果は完了、未確認、確認エラーのいずれかとする。
- 手動確認結果は保存しない。
- Gmail本文、OAuthトークン、Slack Webhook URLは保存しない。

## 10. 公開デモ

- ポートフォリオ閲覧者はGoogleまたはSlackとの連携なしで閲覧できる。
- デモではサンプルデータだけを使用する。
- デモで「今すぐ確認」を実行しても、実際のGmail検索や通知は行わない。
- 実際のメールアドレス、OAuthトークン、Webhook URL、実際の提出状況を公開しない。
- 画面上に「デモデータ」であることを明記する。

## 11. エラー処理

### Gmail認証エラー

- 再ログインが必要な状態として扱う。
- Slackが利用可能なら、Gmailとの再接続が必要であることをSlackへ通知する。

### Gmail APIの一時エラー

- 回数を制限して再試行する。
- 再試行後も失敗した場合は確認エラーとする。

### Slack通知エラー

- Gmail通知は続行する。
- Webhook URLなどの秘密情報を画面、ログ、通知本文へ出さない。

### Gmail通知エラー

- Slack通知は続行する。

### 定期実行エラー

- 実行基盤のログから確認できるようにする。
- 定期実行エラーを利用者へ知らせる別経路が必要かどうかは未決定。

## 12. 公開画面

一画面構成とし、少なくとも以下を表示する。

- アプリ名
- 非公式・個人用であること
- アプリの目的
- 実データまたはデモデータの区別
- 対象月
- 完了、未確認、確認エラーのいずれか
- 完了の場合は完了メールの受信日時
- 「今すぐ確認」ボタン
- Gmail確認から通知までの簡潔な仕組み
- GitHubリポジトリへのリンク

## 13. 受け入れ条件

- 9月の判定で8月以前の完了メールが使用されない。
- 2027年9月の判定で2026年9月の完了メールが使用されない。
- 当月に一致メールがある場合だけ完了になる。
- 完了時にメール受信日時が日本時間で表示される。
- 一致メールがない場合は未確認になる。
- API取得に失敗した場合は未確認ではなく確認エラーになる。
- Slack未設定でも処理がクラッシュしない。
- Slack通知失敗時もGmail通知を試行する。
- Gmail通知失敗時もSlack通知を試行する。
- デモ操作で実メール検索や実通知が行われない。
- 公開ページと公開リポジトリに秘密情報が含まれない。
- 15日の結果が完了で、少なくとも一方の通知が成功している場合、25日はGmail検索も通知も行わない。
- 15日の結果が完了でも両方の通知が失敗している場合、25日に再確認・再通知する。
- 15日の結果が未確認または確認エラーの場合、25日に再確認して現在の結果を通知する。
- 15日の記録が存在しない場合、25日に確認して現在の結果を通知する。
- 25日の両方の通知が失敗しても、その月の追加の定期確認・通知を作成しない。
- 前年または前月の15日の記録によって、当月25日の処理が省略されない。
- 手動確認では画面表示に加えてSlackとGmailへ通知する。
- 手動確認を実行しても、当月25日の実行要否は変わらない。
- 迷惑メールとゴミ箱のメールは完了判定に使用しない。
